1 Introduction

In this practical, we will work through several examples of calculating Bayes Factors using the BayesFactor package (Morey & Rouder, 2024). This is a simple and effective way of incorporating Bayesian methods alongside standard frequentist significance testing. Indeed, some people advocate reporting a “B for every P” (e.g., Dienes & Mclatchie, 2018) to facilitate the interpretation of null findings. You might encounter Bayes Factors as you read recent literature for your other advanced options.

Note that Bayesian modelling is an approach that can be broadly applied, rather than a single statistical method. That is, there are Bayesian versions of pretty much every technique we’ve learned in this module! This means that it can get very complex. However, we will stick to considering how Bayes Factors can supplement the frequentist tests you learned about in Years 1 and 2.

Note

As a reminder, this week’s learning objectives are to:

  1. Recall core principles of frequentist statistics
  2. Describe the philosophy behind Bayesian statistics
  3. Explain how prior and posterior probability distributions are used in Bayesian inference
  4. Compare alternative models by interpreting Bayes Factors as evidence
  5. Discuss the relative merits of frequentist and Bayesian statistical approaches

2 Setting up

2.1 Create a script

Start with the usual set-up steps for the practical sessions:

  1. Open your ARM_Practicals.Rproj file in RStudio
  2. Create a new script and save it in your scripts/ folder as ARM10_Bayes.R

The data we will work with today is the same data that we used for the very first practical, where we learned how to run basic statistical tests in R. If you don’t have this on your current machine, re-download the data from the VLE and save it in your data folder.

2.2 Load packages

Install the BayesFactor package using install.packages() or the packages tab. Once it is installed, you can load it at the top of your script ready for today. You will also need the tidyverse package loaded for some simple data manipulation.

library(BayesFactor)
library(tidyverse)

2.3 Load data

Load the two datasets for today’s session. If you remember, these two datasets looked at working memory capacity in relation to gaming.

# Load data
gamer_dat <- read.csv("./data/ARM1_data1_gamers.csv")
type_dat <- read.csv("./data/ARM1_data2_gametype.csv")

The first dataset (gamer_dat) compared the working memory capacity of gamers and non-gamers, whereas the type_dat dataset focused on the different types of games that gamers played. Inspect the data frames to remind yourself what these looked like.

3 Calculating Bayes Factors for t-tests

In the first practical, we ran a t-test to compare the working memory capacity of gamers and non-gamers. Let’s remind ourselves how to do this:

# Independent samples t-test
t.test(wmc ~ gamer, data = gamer_dat)

You should see that there is a significant difference between groups.

Now let’s calculate a Bayes Factor for this test. We use the specialised t-test function from the BayesFactor package, but everything else is set up in pretty much the same way. The only different is that we must explicitly specify that the first argument we provide is a formula.

# Calculate BF for the t-test
ttestBF(formula = wmc ~ gamer, data = gamer_dat)

You should see that the data provide more support for the alternative hypothesis over the null hypothesis (as the BF >1). However, Jeffreys’ scale would consider this fairly weak or “anecdotal” evidence with a BF10 = 1.95.

Congratulations, you’ve just calculated your first Bayes Factor! It was surprisingly easy, huh?

4 Calculating Bayes Factors for linear regression

Now let’s try for a linear regression: can working memory capacity be predicted by age? As before, let’s start by reminding ourselves of the standard frequentist test:

# Run and print summary of regression
lm_mod <- lm(wmc ~ age_years, data = gamer_dat)
summary(lm_mod)

We again use a specialised function to calculate the Bayes Factor, but everything else remains the same.

# Calculate BF for the regression
lm_bf <- lmBF(wmc ~ age_years, data = gamer_dat)

# Print Bayes Factor
lm_bf

As above, the evidence favours the alternative hypothesis, that working memory capacity is predicted by age. Look back at Jeffreys’ scale: how strong is the evidence?

Perhaps time spent gaming might be a better predictor, given that gamers appeared to have higher working memory capacity in earlier analyses. To look at this question, we first need to filter the dataset to include gamers only, since non-gamers did not answer the question of how long they spent gaming. We can do this using the filter() function from the tidyverse package as follows, specifying that it keeps only rows where the gamer category is equal to (==) “y” for yes:

# Create subset of gamers
gamers_only <- filter(gamer_dat, gamer == "y")

With this new subset of data, test whether working memory capacity (wmc) is predicted by the time spent gaming (hours). Run a frequentist model first, then calculate the Bayes Factor. What does the Bayes Factor add to this analysis and interpretation?

Tip

The function output defaults to H10 — i.e., evidence in favour of the alternative over the null hypothesis. If you instead want to calculate the evidence in favour of the null over the alternative hypothesis (H01), you can inverse your output by running 1/lm_bf2.

5 Calculating Bayes Factors for an ANOVA

Our final test related to whether the type of game matters for working memory capacity, using the second type_dat dataset. We need to instruct R to interpret the type variable as a factor, and then can run a one-way ANOVA as we did in Week 1:

# Game type as factor
type_dat$type <- as.factor(type_dat$type)

# Run and print ANOVA output summary
gametype_mod <- aov(wmc ~ type, data = type_dat)
summary(gametype_mod)

Now use the anovaBF() function to compute a Bayes Factor score.

6 Changing the prior

Remember from the lecture that a defining feature of Bayesian analyses is that we incorporate a prior—our existing expectations about what the data might look like, based on previous evidence. However, we didn’t specify anything about prior knowledge when running the analyses above.

By default, the BayesFactor package uses “weakly informative” prior, meaning that it didn’t incorporate very much in the way of prior knowledge when calculating the Bayes Factors above. This default is a Cauchy distribution with a scale of 0.707—a bit like a normal distribution but with chunkier tails. You can plot this distribution to see what it looks like, using the following line of code:

# Set scale of x axis
x <- seq(-10, 10, by = 0.1)
plot(x, dcauchy(x, scale = 0.707), type = "l")

Using a distribution (rather than a single point estimate) allows us to consider that a range of outcomes are plausible. This default is centered around 0 to indicate that the effect may be in either direction, and expresses that small effect sizes closer to zero are more plausible than very large ones (which are far from 0). This makes it a sensible default for effects we observe in psychology, but doesn’t incorporate any theoretical expectations.

See what happens to your plotted distribution when you change the scale value from lower to higher numbers. How does this affect the width of the prior?

Now let’s see how changing the width of the prior affects the Bayes Factor, using our original t-test example. Try a range of smaller and higher values for the rscale argument. How does the prior affect the conclusions?

# Default 
ttestBF(formula = wmc ~ gamer, data = gamer_dat)

# Alternatives - e.g.,
ttestBF(formula = wmc ~ gamer, data = gamer_dat, rscale = 0.5)
ttestBF(formula = wmc ~ gamer, data = gamer_dat, rscale = 3)

Researchers will often test a range of priors to perform a sensitivity analysis, inspecting how their choice of prior has influenced the results. There is a beautiful illustration of this process by Jim Grange on his blog, or you can continue on to the Challenge yourself section below to have a go at this yourself.

7 Summary

In this session, we used the BayesFactor package to calculate Bayes Factors for a wide range of common statistical tests. We saw how it uses a “default prior” to represent average effect size probabilities, but that we could change it if we had different expectations about our data. This makes the package very easy to use, even with some more complex models that incorporate random effects. Tools such as these make some useful aspects of Bayesian statistics more accessible to a wide range of researchers.

7.1 Challenge yourself

Run a full sensitivity analysis on the t-test analysis above. The aim is to produce a plot that shows how the Bayes Factor changes as the prior scale is increased from 0.1 to 4, in steps of 0.1 (similar to the one linked above).

You will need to create a for loop (like you did in the stochastic methods practical) and extract the Bayes Factor values for each model. Here are some hints:

  • Before your loop, you will need to create an empty list to store Bayes Factors.
  • You might also want to create a variable that starts at 0, then increases by one each time through the loop. You can use this variable to index which row/entry of your list to store the output in each time.
  • You can use the seq() function to specify the different scale values. We used this in plotting above, and you can inspect the help files to see how it works.
  • You can extract the Bayes Factor from the model output as follows: bf_list[n] <- extractBF(bf, onlybf = TRUE) , where bf is the output of the ttestBF() command above, and bf_list is the name of your list to store the output.
  • After you’ve run your loop to calculate the different Bayes Factor values, you should display them in a figure. You can plot your different scale values on the x-axis, and resulting Bayes Factors on the y-axis.

Is the function a straight line, or does it peak around some optimal value? Would your conclusions about these data have changed based on the values of the prior that you selected?
